# 小程序设计规范

`apps/mini` 的视觉与交互规范：设计 token、主题、`ui/` 组件清单、页面版式、无障碍、深色模式。

- 页面见 [pages.md](pages.md)；平台硬性要求见 [wechat-compliance.md](wechat-compliance.md)。
- 本文所有尺寸都是 **750 设计宽度下的 px**。Taro 的 `designWidth: 750` 把 Sass 中的 `px` 按 1:1 转为 `rpx`，所以 `28px` 在 375 pt 宽的屏幕上显示为 14 pt。
- 行内样式里的尺寸必须经 `Taro.pxTransform`，由守卫检查（第 9 节）。

## 1. 原则

### 1.1 微信设计指南

依据：https://developers.weixin.qq.com/miniprogram/design/

指南的四条原则是「友好礼貌、清晰明确、便捷优雅、统一稳定」。落到本项目：

| 原则     | 在本项目中的具体要求                                                                                                                                                                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 友好礼貌 | **不打断用户：**<br>- 开屏浮层每天最多一次，可跳过；<br>- 不在进入页面时弹登录，登录只在动作触发时出现（C05）；<br>- 订阅消息只在用户点击「提交」时请求（C08）；<br>- 首页不叠放多个弹窗，新人券弹窗和开屏浮层互斥，开屏优先。                                                     |
| 清晰明确 | **每页只有一个主操作：**<br>- 商品详情是「立即购买」，结算页是「提交订单」，收银台是「立即支付」；<br>- 主按钮用品牌色实心，其余一律是描边或文字按钮；<br>- 状态要可见：加载用骨架屏，空状态有插图、说明和下一步按钮，错误有原因和「重试」。                                       |
| 便捷优雅 | **减少输入：**<br>- 用微信能力替代手填：手机号快速验证、微信地址、微信发票抬头、`chooseAvatar`、昵称键盘；<br>- 输入框使用正确的 `type`（`number`、`digit`、`idcard`、`nickname`），并设置 `confirm-type`；<br>- 结算页默认选中默认地址和最优券。                                  |
| 统一稳定 | **导航与反馈统一：**<br>- 除首页和「我的」，其他页面使用原生导航栏；<br>- 自定义导航栏必须避开右上角胶囊（`getMenuButtonBoundingClientRect`）；<br>- 反馈统一走 `ui/` 的 `Toast`、`Dialog`、`ActionSheet`，不直接调用 `wx.showModal`，保证样式和文案一致；<br>- 返回行为不被劫持。 |

### 1.2 WeUI 风格

WeUI 是微信官方的基础样式库：https://github.com/Tencent/weui 。我们**不直接使用 WeUI 的组件**（组件都是自建的 `ui/` 组件库；原计划的 NutUI-React-Taro 已删除，见 status/L2-mini.md），但以下几点向 WeUI 看齐，让用户觉得「像微信」：

- **灰底白卡：** 页面底色为浅灰，内容放在白色卡片或 cell 组里；cell 高度 ≥ 96px，分割线用 1 物理像素（hairline）。
- **中性色克制：** 大面积只用黑、白、灰；品牌色只出现在主按钮、选中态、价格、角标上。
- **弹层从底部出：** 选择类操作（规格、地址、券、分享方式）都用底部弹层（`Sheet`），不用居中弹窗；居中 `Dialog` 只用于确认和阻断。
- **Toast 短促：** 一律 1.5 秒；成功无图标，只用文字；只有「加载中」带 loading 图标。

### 1.3 电商惯例

- **价格：** 最醒目的数字。主价格用 `--color-price`，「¥」符号小一号，小数部分也小一号（例如 ¥**199**.00）。划线价用 `--color-text-tertiary` 并加删除线。划线价的依据说明放在商品详情的「价格说明」里（C02）。
- **商品卡：** 图片 1:1，标题最多 2 行，价格单独一行，销量、标签放在最后一行；整卡可点，另有独立的加购按钮（热区 ≥ 88px）。
- **底部操作栏：** 商品详情、结算、订单详情、售后都用固定底栏：左侧是图标入口（客服、购物车、收藏），右侧是 1 到 2 个主次按钮；底栏高 100px，再加安全区。
- **倒计时和库存紧张：** 只对真实的截止时间（拼团到期、预售结束、待支付倒计时）显示倒计时，不做虚假紧迫（C02、C16）。
- **状态颜色表示含义：** 订单和售后状态用文字表达，颜色只是辅助。「待付款」和「退款中」用 `--color-warning-text`，「已完成」用 `--color-text-secondary`，「已关闭」用 `--color-text-tertiary`。

## 2. 设计 token

token 分两类：

| 类别     | 包含                         | 实现                                                                                     | 运营能否修改          |
| -------- | ---------------------------- | ---------------------------------------------------------------------------------------- | --------------------- |
| **颜色** | 第 2.1 节全部                | CSS 变量。`app.scss` 的 `page { … }` 写默认值，运行时由 `theme/store.ts` 覆盖（第 3 节） | 仅第 3.2 节列出的几个 |
| **尺寸** | 字号、间距、圆角、阴影、层级 | Sass 变量（`apps/mini/src/ui/tokens/_size.scss`），编译时确定                            | 否                    |

尺寸不使用 CSS 变量，有两个原因：

1. 尺寸不需要运行时修改；
2. Taro 的 px→rpx 转换对 `var()` 里的数值是否生效没有保证，而 Sass 变量在编译期展开成字面量，一定会被转换。

### 2.1 颜色

所有对比度按 WCAG 2.x 计算，背景是白色 `#FFFFFF`；标「灰底」的是在 `--color-bg` `#F5F5F5` 上的值。目标：正文 ≥ 4.5，大字（≥ 36px 加粗或 ≥ 48px）和图标 ≥ 3。

| token                    | 默认值                            | 用途                                                                                             | 对比度（白 / 灰底）                                     |
| ------------------------ | --------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------- |
| `--color-primary`        | `#E1251B`                         | 品牌主色：主按钮底色、选中态（tab、筛选、复选框）、角标                                          | 4.69 / 4.30                                             |
| `--color-on-primary`     | `#FFFFFF`（自动计算）             | 主色上的文字和图标                                                                               | 4.69                                                    |
| `--color-primary-soft`   | 主色 10% 透明度叠在白色上         | 标签底、选中卡片底、次按钮底                                                                     | —                                                       |
| `--color-primary-text`   | 等于主色，或自动加深（第 3.3 节） | 白底上用主色写的文字（「查看全部」、选中的 tab 文字）                                            | ≥ 4.5                                                   |
| `--color-accent`         | `#FF7E00`                         | 辅助色：渐变按钮的起点、「加入购物车」次按钮的底色（与主色并排）；**不用于小字**                 | 2.55（只作底色，上面的文字用 `--color-on-accent`）      |
| `--color-on-accent`      | `#FFFFFF`（自动计算）             | 辅助色上的文字；实心按钮上的文字 ≥ 30px 加粗，按大字标准 ≥ 3 判定，不足时自动改为 `#1A1A1A`      | —                                                       |

| `--color-text-disabled`  | `#B2B2B2`                         | 禁用文字；**只用于禁用态**，WCAG 对禁用控件不做要求                                              | 2.12                                                    |
| `--color-bg`             | `#F5F5F5`                         | 页面底色                                                                                         | —                                                       |
| `--color-surface`        | `#FFFFFF`                         | 卡片、cell、弹层、底栏                                                                           | —                                                       |
| `--color-surface-sunken` | `#F7F7F7`                         | 卡片内的次级块（地址块底、订单商品行底、搜索框底）                                               | —                                                       |
| `--color-mask`           | `rgba(0, 0, 0, 0.6)`              | 弹层遮罩                                                                                         | —                                                       |
| `--color-border`         | `#E5E5E5`                         | 分割线、描边按钮的边框（hairline）                                                               | 装饰线，不要求对比度                                    |
| `--color-border-strong`  | `#8C8C8C`                         | 输入框、复选框、单选框的边框（控件边界需要 ≥ 3）                                                 | 3.36                                                    |
| `--color-success-text`   | `#0F7B3F`                         | 成功文字（「已支付」「领取成功」）                                                               | 5.35                                                    |
| `--color-success`        | `#07C160`                         | 只用于「微信支付」品牌标识和结果页的成功插图（装饰，旁边一定有文字说明）；不作按钮底色，不写文字 | 2.38（达不到图标的 3，所以只作装饰）                    |

| `--color-skeleton`       | `#EEEEEE`                         | 骨架屏块                                                                                         | —                                                       |

**关于默认主色 `#E1251B`：**

- 旧版的默认红色是 `#E93323`（`apps/uni-app/api/mappers/diy.js:49`），在白底上只有 4.23，白字放在它上面也是 4.23，都达不到 4.5。
- `#E1251B` 与它肉眼几乎看不出区别，但两个对比度都过线。
- 运营在旧版选过的主题色原样保留，过线靠第 3.3 节的自动派生，不改运营的数据。

**旧版一键换色的另外四种颜色：**

| 颜色         | 白底对比度 | 情况                   |
| ------------ | ---------- | ---------------------- |
| 蓝 `#1DB0FC` | 2.42       | 做按钮底色，白字不过线 |
| 绿 `#42CA4D` | 2.15       | 同上                   |
| 粉 `#FF448F` | 3.24       | 同上                   |
| 橙 `#FE5C2D` | 3.10       | 同上                   |

这正是需要第 3.3 节自动派生的原因。

### 2.2 字号

字体一律用系统字体栈，不打包字体文件（体积预算，C13）。

- 字体栈：`-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Helvetica Neue', 'Microsoft YaHei', sans-serif`。
- 数字（价格、倒计时）加 `font-variant-numeric: tabular-nums`，避免跳动时宽度变化。

| Sass token       | 字号 / 行高 | 字重 | 用途                                                       |
| ---------------- | ----------- | ---- | ---------------------------------------------------------- |
| `$font-display`  | 48 / 64     | 600  | 支付结果金额、商品详情主价格的整数部分                     |
| `$font-title-lg` | 36 / 50     | 600  | 页面内大标题（支付结果状态、空状态标题）、自定义导航栏标题 |
| `$font-title`    | 32 / 44     | 600  | 卡片标题、商品详情标题、弹层标题                           |
| `$font-body-lg`  | 30 / 42     | 400  | cell 主文字、按钮文字（大按钮）、输入框                    |
| `$font-body`     | 28 / 40     | 400  | **正文默认**：商品卡标题、订单商品名、说明文字             |
| `$font-caption`  | 24 / 34     | 400  | 辅助信息：规格、时间、销量、表单提示                       |
| `$font-small`    | 22 / 30     | 400  | 标签文字、tab 栏文字、价格的「¥」符号和小数部分            |
| `$font-micro`    | 20 / 28     | 500  | **仅限**角标数字（购物车数量、未读数）；不用于句子         |

规则：

- 正文不小于 28，任何可读的句子不小于 22。
- 页面根节点**跟随微信的字体大小设置**：`<PageMeta pageFontSize="system" rootFontSize="system" />`（基础库 2.11.0；`page-meta` 必须是页面的第一个节点）。参考：https://developers.weixin.qq.com/miniprogram/dev/component/page-meta.html
- 版式要能承受 1.3 倍放大：
  - 文字容器不写死高度；
  - 按钮用 `min-height`；
  - 单行文字加省略号，多行用 `-webkit-line-clamp`。

### 2.3 间距

基准是 4 的倍数；页面里只允许使用下表中的 token，由 stylelint 规则检查。

| token      | 值  | 典型用途                               |
| ---------- | --- | -------------------------------------- |
| `$space-1` | 8   | 图标与文字、标签之间                   |
| `$space-2` | 12  | 卡片内的行间距                         |
| `$space-3` | 16  | 商品网格的列间距、cell 内元素间距      |
| `$space-4` | 20  | 卡片之间的垂直间距                     |
| `$space-5` | 24  | **页面左右边距（gutter）**、卡片内边距 |
| `$space-6` | 32  | 分组之间                               |
| `$space-7` | 40  | 空状态、结果页的大块留白               |
| `$space-8` | 48  | 结果页图标与标题                       |
| `$space-9` | 64  | 结果页顶部留白                         |

- 商品网格双列：`(750 − 24 × 2 − 16) / 2 = 343`，每列宽 343。
- 单个可点元素的热区 ≥ 88 × 88。视觉上小于这个尺寸的（复选框 40、关闭图标 32），用 padding 或伪元素扩大热区。

### 2.4 圆角

| token          | 值  | 用途                        |
| -------------- | --- | --------------------------- |
| `$radius-xs`   | 4   | 标签、角标                  |
| `$radius-sm`   | 8   | 输入框、小图（订单商品图）  |
| `$radius-md`   | 16  | 卡片、商品图、弹窗 `Dialog` |
| `$radius-lg`   | 24  | 底部弹层的顶部两个角        |
| `$radius-pill` | 999 | 按钮、搜索框、胶囊标签      |

DIY 块的圆角由装修属性控制（例如商品块的「圆角 / 直角」），取值只能从上表选择。

### 2.5 阴影

原则上**不用阴影区分层级**，靠「灰底 + 白卡」区分，这也符合 WeUI 的扁平风格。只保留两档：

| token           | 值                                | 用途                                         |
| --------------- | --------------------------------- | -------------------------------------------- |
| `$shadow-bar`   | `0 -2px 12px rgba(0, 0, 0, 0.06)` | 固定底栏（与滚动内容分开）                   |
| `$shadow-float` | `0 8px 24px rgba(0, 0, 0, 0.12)`  | 浮动按钮（回到顶部、悬浮购物车）、吸顶筛选条 |

### 2.6 层级（z-index）

| token        | 值   | 用途                                         |
| ------------ | ---- | -------------------------------------------- |
| `$z-sticky`  | 100  | 吸顶的 tab、筛选条、自定义导航栏             |
| `$z-bar`     | 200  | 固定底栏、悬浮按钮                           |
| `$z-overlay` | 900  | 遮罩                                         |
| `$z-sheet`   | 1000 | 底部弹层、`Dialog`、`PrivacySheet`、开屏浮层 |
| `$z-toast`   | 2000 | `Toast`                                      |

- 原生 tabBar、导航栏、`web-view` 与原生组件（`video`、`map`、`canvas` 2D 之外的 `canvas`）不受 z-index 约束，不在此表中。
- 弹层打开时，页面上的 `video` 必须暂停并隐藏，否则会盖住弹层。

### 2.7 安全区与系统区域

| 区域                | 处理方式                                                                                                                                                                                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 底部（Home 指示条） | 固定底栏和底部弹层的内容区加 `padding-bottom: env(safe-area-inset-bottom)`（Sass mixin `@include safe-bottom($extra)`）。tab 页使用原生 tabBar，微信已经处理安全区，**不要重复添加**。                                                     |
| 顶部（状态栏）      | 只有自定义导航栏的页面（首页、我的）需要处理。`useNavBarMetrics()` 从 `getWindowInfo().statusBarHeight` 和 `getMenuButtonBoundingClientRect()` 算出导航栏高度 = `状态栏高度 + (胶囊.top − 状态栏高度) × 2 + 胶囊.height`，结果缓存到内存。 |
| 右上角胶囊          | 自定义导航栏上的内容（搜索框、门店名）右边界 ≤ `胶囊.left − 16px`（设备像素，不是 rpx）。胶囊区域不放任何可点元素（C16：遮挡胶囊会被驳回）。                                                                                               |
| 横屏 / iPad         | `app.json` 不开启 `pageOrientation: auto`。在 iPad 等宽屏上，750 设计宽度会等比放大；商品网格在屏宽 ≥ 768pt 时改为 3 列（`useWindowWidth`），避免图片过大。                                                                                |

## 3. 主题

### 3.1 注入方式

- **默认值：** `apps/mini/src/app.scss` 在 `page { … }` 中写第 2.1 节的全部颜色变量。在小程序里，`page` 选择器就是根节点。
- **运行时覆盖：** 每个页面最外层是 `ui/PageShell`，第一个节点是 `<PageMeta pageStyle={themeStyle} pageFontSize="system" rootFontSize="system" />`。`themeStyle` 是 `theme/store.ts`（`useThemeStore`）从 `app/config.appearance.theme` 算出的一串 `--color-*: …;`。
- 用 `page-meta` 而不是在某个 `View` 上写 style，是因为 `page-style` 作用于页面根节点，**底部弹层、Toast 等挂在根下的节点也能继承**，不会出现「弹层还是默认红色」的问题。
- `app/config` 带 ETag，本地缓存。冷启动先用缓存的主题渲染，再在后台刷新，避免主色从默认值闪变为店铺的颜色。
- **原生区域**不受 CSS 影响，由 `platform/tab-bar.ts` 在启动时和主题变化后调用 API：
  - `setTabBarStyle({ color, selectedColor, backgroundColor, borderStyle })`：选中色等于 `--color-primary-text`，未选中色 `#666666`，背景 `#FFFFFF`，`borderStyle: 'white'`；
  - `setTabBarItem`：只改文字；图标用打包在主包里的 4 组 PNG（81 × 81，每个 ≤ 40 KB），不从网络加载；
  - `setNavigationBarColor`：原生导航栏统一为白底黑字，不跟随主题（微信限制 `frontColor` 只能是 `#000000` 或 `#ffffff`，白底黑字最稳妥）；
  - 购物车数量用 `setTabBarBadge`。

### 3.2 运营可以修改的 token

对应后台「系统设置 → 小程序外观」（配置分组 `storefront-appearance`）和 `app/config.appearance`。这组字段本身就有类型（契约 `appAppearance`，颜色一律 `#RRGGBB`，保存时校验），就是这里说的「v2 token」：

| 字段（`app/config.appearance`） | 配置字段                 | 对应 token                                 | 说明                                          |
| ------------------------------- | ------------------------ | ------------------------------------------ | --------------------------------------------- |
| `theme.primaryColor`            | `primaryColor`           | `--color-primary`（再派生 on、soft、text） | 品牌主色                                      |
| `theme.accentColor`             | `accentColor`            | `--color-accent`（再派生 on）              | 辅助色；为空时是 `null`，等于主色（单色方案） |
| `theme.priceColor`              | `priceColor`             | `--color-price`                            | 价格色；不过线时按第 3.3 节加深               |
| `theme.radius`                  | `radius`                 | `--radius-factor`                          | 圆角档位                                      |
| `tabBar.selectedColor` 等       | `tabBarSelectedColor` 等 | tabBar 颜色                                | 另有 4 个 tab 的文字和图标                    |

**旧的 `diyThemeTokens` 不改类型**（原计划由 F1 改成有类型的 schema，H3 评估后决定不做）：

1. 它是旧 `diy` 域「一键换色」的数据，线上的 uni-app 读 `tokens.theme`（`apps/uni-app/api/mappers/diy.js` 的 `pageColorStatus`），后台 DIY 编辑器读 `theme` 和 `accent`。原计划把 `theme` 改名为 `primary`，会让线上 uni-app 的换色失效，违反「旧前端照常工作」。
2. 只改 TypeScript 类型、不改运行时校验做不到诚实：线上库里的 token 包是运营随意保存过的，把 `Record<string, unknown>` 声明成 `{ theme?: string; … }` 等于对类型撒谎；而加上 zod 校验，又会改变旧接口 `PATCH /admin-api/diy/themes/:id` 接受什么，这是旧行为的改变。
3. 小程序根本不读它：小程序的主题来自上表，已经有类型。切换完成、旧 uni-app 下线后，`diy` 主题整个退役，不需要再迁移。

其余 token（文字灰阶、背景、边框、语义色、全部尺寸）**不开放**。理由：

1. 这些颜色决定可读性和状态含义，改坏的代价高；
2. 旧版开放了十几个颜色变量（`apps/uni-app/utils/theme.js:39-53`），但实际上被运营修改的只有主色和辅助色；
3. 单个 DIY 块内部的颜色（背景、标题色）已由装修属性控制，不需要全局 token。

### 3.3 可读性的自动派生（写入 `packages/contracts`，前后端共用）

`deriveTheme(tokens)` 是一个纯函数，放在 `packages/contracts/src/system/theme.ts`（本身不依赖 zod，小程序可以直接在运行时 import；输入用 `themeInputOf(app/config.appearance.theme)` 得到）。后台预览和小程序调用同一份实现（不变量 SYS-021）：

1. `on-primary`：白色和 `#1A1A1A` 中与主色对比度较高的那个。
2. `primary-text`：如果主色在白底上 ≥ 4.5，就等于主色；否则在 HSL 中逐步降低亮度，直到 ≥ 4.5。例如蓝 `#1DB0FC` 会被加深为约 `#0077B3`。
3. `price`：同第 2 条的规则。
4. `on-accent`：同第 1 条。

**后台的提示：** 主题编辑器在颜色旁显示派生结果和对比度。当主色本身不足 4.5 时提示「按钮文字将自动改为深色」「文字将使用加深后的颜色」，**不阻止保存**。运营选择的品牌色是经营决定，我们只保证文字可读。

## 6. 动效

- **时长：** 进入和展开 200ms，退出 150ms；缓动用 `cubic-bezier(0.2, 0, 0, 1)`。
- **弹层：** 底部弹层从下方滑入，遮罩淡入。
- **加购反馈：**
  - 按钮先轻微缩放（0.96 → 1）；
  - 然后 toast「已加入购物车」，同时 tab 角标 +1；
  - 不做抛物线飞入动画：实现成本高，在低端机上容易掉帧。
- **减弱动效：** 小程序没有 `prefers-reduced-motion`，所以骨架屏的闪光和轮播的自动播放都做成可关的开关（`app/config`），默认开启。自动轮播的间隔 ≥ 4 秒，用户手动滑动后暂停。

## 8. 深色模式：本期不开启

**决定：** v1 的 `app.json` 不设置 `darkmode: true`，不提供 `theme.json`。微信在深色模式下会继续按浅色渲染本小程序（深色模式是可选能力：https://developers.weixin.qq.com/miniprogram/dev/framework/ability/darkmode.html ）。

**理由：**

1. **运营内容无法自动适配。** 首页、我的、微页面的 DIY 块自带背景色、文字色和图片（很多 banner 是带白底的设计图）。开启深色后，我们的外框会变深，但运营的内容仍是浅色，会出现「深色页面里夹着一块块白底 banner」的效果，比不支持更差。要做好，必须让每个 DIY 块再配一套深色属性，运营的工作量翻倍。
2. **商品图多为白底。** 电商主图普遍是白底，在深色卡片上会变成一个个白方块；主流电商小程序也不跟随深色模式。
3. **品牌色需要重新校验。** 第 3.3 节的派生规则针对白底；深色底需要另一套派生和校验，这是第二份设计工作。
4. **不影响上线和审核。** 深色模式不是审核要求。

**为以后开启保留的条件：**

- 所有颜色都经过语义 token（第 2.1 节），页面中不出现十六进制颜色（stylelint 的 `color-no-hex` 只在 `ui/tokens/` 中允许），所以以后只需在 `@media (prefers-color-scheme: dark)` 下再定义一份 `page { … }` 变量；
- 原生区域（导航栏、tabBar、背景）的颜色都已集中在 `platform/tab-bar.ts`，以后可以改为 `theme.json` 的 `@变量`；
- 真正的前置工作是 DIY 块的深色属性。这是产品决定，列入待确认事项。
