# Spike S3: DIY v2 page decoration with Puck and shared blocks

Branch `storefront/mini-S3-decor`. Date 2026-09-23.

**Verdict: GO with Puck 0.23.0**, on the conditions at the end. Three blocks (carousel, product
grid, image cube) are written once, in `@tarojs/components` + Sass on a 750 design width. The
mini-program compiles them with Taro. The admin renders the same source in Puck's 375 px canvas,
through a DOM shim and a px → vw stylesheet. The editor is driven entirely by the blocks' zod
schemas. Puck's data round-trips to the v2 page document without loss. Canvas and Taro H5 differ by
0.18 % to 2.67 % of pixels per block, and the text layout and box geometry match. All the
Puck-aware code, about 1,100 lines including the antd fields, is in `apps/web/src/admin/decor/`.
The schemas, blocks, document format and shim do not depend on Puck, so the fallback below stays
cheap if Puck later has to go.

```
  src/dom/                           the DOM shim for @tarojs/components (View, Text, Image, Swiper,

  scripts/build.ts, css-modules.ts   esbuild + sass + postcss px→vw → dist/admin.{js,css}, dist/admin-css.js
  scripts/gen-css-types.ts           *.module.scss.d.ts (committed; regenerated by `gen`)
  fidelity/run.ts                    Playwright + pixelmatch, not in CI
apps/web/src/admin/decor/            the editor wrapper (the only Puck-aware code)
  zod-to-puck.ts                     zod schema → Puck fields (+ defaultsOf for new array items)
  fields.tsx                         image / link / colour / product-source custom fields on the antd pickers
  config.tsx                         Puck Config built from the block registry; error boundary per block
  document.ts                        Puck Data ⇄ v2 PageDocument, refusing what it cannot map
  editor.tsx                         <DecorEditor>: Puck with a 375 px iframe canvas and our CSS only
apps/web/app/admin/(shell)/dev/decor-spike/   dev-only page (menu 开发 → 装修编辑器试验)
apps/mini/src/subpackages/demo/pages/blocks/   dev-only page rendering the three blocks on fixtures
docs/mini/spikes/S3/                 screenshots, diffs, fidelity.json
```

The document the editor saves:

```ts
{ schemaVersion: 2, root: { props: { title, background?, shareTitle? } },
  blocks: [{ id, type: 'carousel' | 'productGrid' | 'imageCube', v: 1, props }] }
```

`toPuckData` refuses an unknown block type and a block whose `v` differs from the registry's. It
does not guess, so a migration has to run first. `toPageDocument` refuses non-empty Puck zones,
because the v2 format has no nesting. A block's props are validated by its schema. A new block
starts **invalid** until its images are picked (the error is `请选择图片`), and the page lists the
issues. Publishing would be blocked on them.

## How the pieces fit

**One source, two renderers.** The blocks import `@tarojs/components` and their own
`*.module.scss`.

- **Mini-program.** Taro compiles them from source: `apps/mini` adds `packages/storefront-blocks/src`
  to `workspaceSources`, the same mechanism S1 uses for `@shop/contracts`. pxtransform turns design
  px into rpx (WeChat) or rem (H5).
- **Admin.** The package's `gen` step builds `dist/admin.js`. esbuild bundles the blocks with
  `@tarojs/components` aliased to the shim. Sass output goes through a postcss px → vw plugin
  (`px / 750 × 100 vw`, rounded to 1e-5), then esbuild's `local-css` loader, so the class names in
  JS and CSS always agree. The CSS also ships as a string (`dist/admin-css.js`), which the editor
  injects into Puck's iframe.
- **Why this works.** In a 375 px iframe, 750 design px is exactly the frame width, as on a phone.
  Next needs no sass, no alias and no PostCSS scoping for the canvas.
- **Dynamic sizes** go through CSS custom properties that hold design px, for example
  `height: calc(var(--sb-height) * 1px)`. Both pxtransform and the vw plugin convert the `1px`, so a
  schema value in design px means the same thing on both sides.

**The editor is schema-driven.** `zodToPuckFields(schema, customRenderers)` maps:

| zod                                          | Puck field                                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `z.enum` / union of literals                 | `radio` if ≤ 3 choices or `meta.field: 'radio'`, else `select`; typed values                      |
| `z.boolean()`                                | `radio` 开/关 over real booleans (Puck has no switch)                                             |
| `z.string()`                                 | `text`, or `textarea` via meta; `placeholder` from meta                                           |
| `z.number()` with min/max                    | `number` with min/max, `step` from meta                                                           |
| `z.array(z.object(...))` with min/max        | `array` with min/max, `defaultItemProps` from schema defaults, item summary from `meta.itemLabel` |
| `z.object(...)`                              | `object`                                                                                          |
| `meta.field: image/link/color/productSource` | `custom`, rendered by the admin's antd controls                                                   |
| `meta.hidden`                                | omitted                                                                                           |
| anything else                                | **throws** (or uses the optional `unsupported` JSON renderer)                                     |

The custom fields reuse the existing admin kit:

- **Image.** `AssetPicker` plus a URL input.
- **Link.** The `LinkTarget` kinds: product and article through `DiyPickerModal`, category through
  a `TreeSelect`, a storefront route from a list, webview, and another mini-program (appId + path).
  `page` is still a plain input stub. `不跳转` is offered only when the schema field is optional.
- **Colour.** antd `ColorPicker`, stored as hex.
- **Product source.** 手动 (a list with the picker, max 20), or 分类 (category + sort + limit).

The canvas resolves a product source to cards through a `DecorCanvasData` context, which is fixture
data in the spike and a query later.

## Integration issues and their fixes

1. **Next 16 and a source-first package.**
   - `@shop/storefront-blocks` is added to `transpilePackages`, for `./schema` and `./fixtures`.
   - The blocks themselves reach Next only as the prebuilt `dist/admin.js`. Next's CSS pipeline
     cannot apply a PostCSS plugin to one package, and it cannot produce class names that match a
     stylesheet built elsewhere.
   - `apps/web/tsconfig.json` maps `@tarojs/components` to the shim source. This lets
     `apps/web`'s typecheck see the block source (under React 19 types) without Taro installed.
2. **React 18 and 19 at the same time.**
   - The package is typechecked against **React 18 types**, via `paths` to
     `@types/react@18.3.31` aliases, so a 19-only API does not compile. `apps/web` checks the same
     source against 19.
   - Render tests run twice. The `unit` project runs on React 19. The `unit-react18` project uses
     the `react-18` / `react-dom-18` npm aliases.
   - pnpm links the aliased `react-dom@18` against the workspace's React 19 (peer resolution), which
     fails with `ReactCurrentDispatcher` undefined. `src/test/react18-hooks.ts` fixes this with a
     `module.registerHooks` resolve hook that points `react` imports coming from `react-dom@18.*` at
     `react-18`. A test asserts that both majors match the project.
3. **sass.** `auto-install-peers` picked sass 1.105.0, which was inside the workspace's
   `minimumReleaseAge` window. `pnpm-workspace.yaml` now has `overrides: sass: 1.104.1`, so no
   release-age exception is needed.
4. **The iframe gets our styles only.**
   - `iframe.syncHostStyles: false` keeps antd's reset and the admin globals out of the canvas.
     Puck still injects its own canvas CSS, which is harmless.
   - Our CSS goes in through `overrides.iframe({ document })`, as a `<style>` element.
   - Puck's auto-zoom scales the canvas down (77 %) whenever the editor is narrower than about
     1100 px: two side panels plus 375 px. The spike page gives the editor full width. Puck's zoom
     select is the escape hatch, and the fidelity script sets it to 100 %.
5. **Puck quirks worth knowing.**
   - Puck renders the fields panel **twice**, one copy hidden, so tests must scope their selectors.
   - Custom fields render their own label (`FieldLabel`).
   - Render props arrive with `id`, `puck` and `editMode` mixed in; `ownProps` strips them.
   - There are no field groups, no help text and no switch field. We use a boolean radio, and help
     would have to go in the label or in a custom field.
   - A block that throws while rendering would take down the canvas. Each block is wrapped in an
     error boundary that shows `「块名」：当前配置无法预览` and resets when its props change.
6. **Taro compiling a workspace package (apps/mini).** Two resolver changes in
   `apps/mini/config/index.ts`, beyond the page and its `app.config` entry:
   - **`react` alias** to `apps/mini/node_modules/react`. Without it the package's own
     `node_modules/react` wins: that is the React 19 devDependency used for tests. React 19 elements
     then reach the React 18 reconciler, which fails with minified React error #31 and renders
     nothing.
   - **`resolve.modules` fallback** to `apps/mini/node_modules`, after the normal walk. Taro
     rewrites `@tarojs/components` to `@tarojs/plugin-platform-weapp/dist/components-react`, which a
     file under `packages/` cannot reach. Taro leaves `resolve.modules` empty, so the walk is
     restated first as `['node_modules', <apps/mini>/node_modules]`.
   - After both changes, `pnpm --filter @shop/mini build` passes and size-report says `react×1`.
7. **Fidelity environment.**
   - WSL has no CJK fonts, so text rendered as tofu boxes. The fidelity run used a private
     fontconfig (`FONTCONFIG_FILE`) with Microsoft YaHei copied from Windows. Nothing was installed
     system-wide.
   - Admin shots are clipped to each block's box snapped to device pixels.
   - The canvas sits at a fractional offset (x 914.5, y 379.14), which is nudged onto the pixel
     grid. Element screenshots would round the boxes outwards into grey edges.

## Shim gaps

The shim's goal is the **WeChat** behaviour, and its structural CSS sits under `:where()` so a
block's class always wins. Known gaps:

| Component    | Gap                                                                                                                                                                                                                                                      |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Swiper`     | `circular` wraps backwards (no cloned slides); no `previousMargin` / `nextMargin` / `easingFunction`; a fixed 40 px drag threshold, no momentum or velocity paging                                                                                       |
| `Swiper`     | indicator follows WeChat (`indicatorColor` as given). Taro **H5** renders inactive dots almost invisibly (swiper.js bullet opacity), and this is the carousel's whole diff                                                                               |
| `Image`      | modes via `object-fit` / `object-position`. `widthFix` / `heightFix` via auto size. `lazyLoad` → `loading="lazy"`. No `showMenuByLongpress` / `webp` flags                                                                                               |
| `Text`       | no `decode`. `space` via CSS classes. No `numberOfLines`: blocks clamp lines with CSS                                                                                                                                                                    |
| `ScrollView` | no `enableFlex` (use a flex child). No refresher, `scrolltoupper` / `scrolltolower`, or `enhanced`                                                                                                                                                       |
| `View`       | `hoverClass` approximated with pointer events (`hoverStartTime` ignored). `catchMove` accepted, not enforced                                                                                                                                             |
| all          | `style` must be an object (Taro also takes strings). Events carry a subset of `BaseEventOrig` (`type`, `timeStamp`, `detail`, `currentTarget/target.{id,dataset}`, `stopPropagation`, `preventDefault`). Only `tap`, `change`, `scroll`, `load`, `error` |

These gaps are acceptable for an editor preview, which is not interactive beyond selection. A block
that needs one of these features must either stay within the shim or extend it, with a test in
`src/dom/dom.test.tsx`.

## Fidelity

`pnpm --filter @shop/storefront-blocks fidelity -- --admin <next start> --h5 <taro h5>` captures
two sides:

- the Puck canvas at `/admin/dev/decor-spike`, with every `/admin-api` request stubbed in the
  browser (no DB and no sign-in);
- the Taro H5 build of `pages/blocks`, served statically.

Both run at 375 px wide with DPR 2. The script then runs pixelmatch (threshold 0.1) per block. Its
output is in `docs/mini/spikes/S3/`: `admin-*.png`, `h5-*.png`, `diff-*.png`, `admin-editor.png`
and `fidelity.json`.

| Block       | Size (device px, both) | Mismatched | %      | What differs                                                                                                                                                                  |
| ----------- | ---------------------- | ---------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| carousel    | 750 × 340              | 458        | 0.18 % | the three indicator dots only (Taro H5's bullet opacity, see the shim gaps)                                                                                                   |
| productGrid | 750 × 1588             | 27 457     | 2.31 % | glyph edges shifted ≤ 1 device px: vw (4.99999 px) vs rem rounding; card edges 1 px                                                                                           |
| imageCube   | 750 × 380              | 7 610      | 2.67 % | the large cell: Taro H5's `aspectFill` sizes the `<img>` 175 × 180 for a 1:1 picture and letterboxes the SVG, while the shim crops it with `object-fit: cover` as WeChat does |

Block heights agree to within 0.05 CSS px (for example 169.98 vs 170), and the layout, line breaks,
clamping and prices match. The residual is sub-pixel rasterisation plus two **Taro H5** emulation
quirks. On those two, the canvas is closer to WeChat than H5 is. This is not a comparison with a
real WeChat renderer. Checking against the devtools or a device is an open question below.

## Recommendation: GO with Puck 0.23.0

Puck earns its place:

- It handles drag-and-drop ordering, an iframe canvas at phone width, selection outlines and
  undo/redo.
- It accepts our own field controls, so the existing antd pickers are reused unchanged.
- It stores plain JSON that maps 1:1 onto the v2 document.
- It works on React 19, is MIT-licensed, and its weight stays on one lazy route.

Conditions:

1. **Keep the boundary.**
   - Only `apps/web/src/admin/decor/{editor,config,zod-to-puck,document}.ts(x)` may import Puck.
   - Routes use `<DecorEditor>` and the conversion functions.
   - The stored format is the v2 document, never Puck `Data`.
   - A guard that forbids `@puckeditor/core` imports elsewhere is cheap to add.
2. **Pin exact and upgrade deliberately.** Puck is pre-1.0, so a minor may break the config,
   field or override APIs. The round-trip and canvas tests are the upgrade gate.
3. **Every schema shape needs a control.** `zodToPuckFields` throws on shapes it cannot map, so a
   new block cannot silently lose a field.
4. **Settle the admin-page layout for the real editor.** Full-width, or accept Puck's auto-zoom
   below about 1100 px.
5. **Verify on WeChat.** Before F-stream blocks multiply, confirm the shim's WeChat assumptions
   (indicator colours, `aspectFill`) against the WeChat devtools once.

**Fallback, if a condition fails:**

- an antd sidebar form generated from the same schemas (the `zodToPuckFields` logic retargeted to
  antd `Form` items);
- a block list with up/down/delete in place of drag-and-drop;
- a Taro H5 build of the storefront in an iframe as the preview, fed by `postMessage`.

The fallback reuses the schemas, blocks, document format and pickers unchanged. It gives up Puck's
drag-and-drop, in-canvas selection and undo, and makes the preview depend on a running H5 build. The
estimated cost is 1–2 weeks. Nothing built here would be thrown away except `editor.tsx` and
`config.tsx`.

## Deviations from the brief

- `apps/mini/config/index.ts` changed as well as the page and its `app.config` entry: the `react`
  alias and the `resolve.modules` fallback (issue 6). Without them the page does not build (weapp)
  or does not render (H5).
- `apps/mini/package.json` gains `@shop/storefront-blocks: workspace:*`, and the lockfile has a
  3-line importer change.
- The blocks reach Next as a prebuilt bundle (`dist/admin.js`), not as transpiled source. See issue
  1 for why.
